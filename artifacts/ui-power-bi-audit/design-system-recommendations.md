# Design System Recommendations

## Current System Evidence

- Framework: Nuxt 3.21.8, Vue 3.5, Vuetify 4.1, Tailwind CSS 4, MDI icons, ApexCharts, MapLibre. Evidence: `package.json`, `nuxt.config.ts`.
- Theme tokens: `nuxt.config.ts` defines `amaLight` and `amaDark` colors; `app/assets/css/theme.css` mirrors brand and semantic CSS variables.
- Icons: MDI via Vuetify/`@mdi/font`.
- Chart wrapper: `app/components/feature/ApexChart.client.vue` and `app/components/charts/FeatureApexChart.client.vue`.
- Generic cards/status: `app/components/ds/StatCard.vue`, `app/components/ds/StatusBadge.vue`.
- Finance-specific shell: `FinancePageHeader`, `FinancePanel`, `FinanceKpiCard`.

## Color Model

Separate these palettes:

1. **Brand colors**
   - Primary navy `#082B49`
   - Secondary teal `#0E8C8A`
   - Cenderawasih accent `#F47A1F`
   - Use for navigation, links, selected states, primary actions, brand accents.

2. **Chart categorical colors**
   - Must not reuse operational `danger/success/warning` as ordinary categories.
   - Use a neutral categorical palette with 8-10 colors that are color-blind safer.
   - Reserve red/yellow/green only when visual encoding is explicitly status/risk.

3. **Operational semantic colors**
   - Danger: safety blocker, unserviceable, AOG, failed/rejected, expired.
   - Warning: pending, stale, incomplete, needs review, overdue soon.
   - Success: approved, posted, confirmed, serviceable only when data truly means serviceability.
   - Info: neutral system state, context, draft where not risky.

`DsStatusBadge.vue` currently maps many statuses into success/warning/danger by string list. This is practical, but should move to domain-specific semantic maps to avoid green meaning both workflow complete and aircraft safe.

## Typography and Density

- Keep Inter/system sans; use tabular numeric formatting for KPIs/tables.
- Report pages should use compact headings; no oversized dashboard hero treatment.
- Operational pages should prioritize dense scan rows and clear actions.
- Cards should use 8px radius or less for app/tool surfaces; current Vuetify default `VCard rounded="lg"` may be slightly too soft for dense ERP.

## KPI Card v2

Required fields:

- metric name
- value
- unit/currency/timezone
- period
- comparison period
- target
- variance and direction
- status
- metric definition
- source
- last updated
- data status: live, near-real-time, snapshot, historical, stale, partial

Rules:

- Do not show a KPI as decoration.
- Do not color a KPI green unless the metric semantics define good/bad direction.
- If comparison is unavailable, explain why or hide comparison consistently.

## Filter Components

Create these primitives:

- `ReportFilterBar`: visible common slicers.
- `ActiveFilterChips`: active filter summary, clear-one, reset-all.
- `AdvancedFilterDrawer`: less common filters, collapsed by default.
- `FilterScopeIndicator`: report/page/visual scope.
- `ShareableFilterUrl`: query serialization/deserialization.

Avoid permanent right filter panel in operational workspaces because station/MRO/accounting task queues need horizontal working space.

## Chart Components

Create a report visual wrapper:

- title/subtitle
- source/updated status
- visual header menu
- focus mode
- show data
- export if allowed
- metric definition
- loading/empty/error/stale states
- accessible table fallback

Chart titles should describe what is plotted, not infer unsupported conclusions. Chart colors must follow semantic/categorical separation.

## Table Taxonomy

1. **Operational data table**
   - Goal: act on rows.
   - Required: sticky header, primary identifier, status, owner, next action, safe row action, loading/empty/error, permission-disabled actions.
   - Avoid spreadsheet overload.

2. **Analytical matrix**
   - Goal: compare and aggregate.
   - Required: hierarchy expansion, subtotal/grand total, numeric alignment, conditional formatting, export, show source.

3. **Printable report**
   - Goal: produce governed output.
   - Required: period, entity, generated by, generated at, source, page breaks, export/print.

4. **Transaction ledger**
   - Goal: trace accounting/audit events.
   - Required: posted/draft/reversed status, source transaction link, audit trail, immutable evidence, debit/credit alignment.

## State Components

Standardize:

- Loading: skeleton shape should match final layout.
- Empty: state should echo active filters and reset action.
- Error: retry + source/API context + whether stale data remains visible.
- Forbidden/blocked: requested action, active role, missing permission, safe next step.
- Stale: age, threshold, refresh action, whether data can be used for action.

## Accessibility

Baseline: WCAG 2.2 AA.

- Ensure visible keyboard focus on all action buttons, tabs, filters, table rows, and chart visual headers.
- Use semantic tables for data tables.
- Provide chart table alternative via show-data.
- Do not rely on color only; add icon/text state.
- Tooltip content must not contain essential-only information.
- Test high-contrast mode and reduced motion.
- Fix mobile clipping before any report polish; clipped text is an accessibility failure.
